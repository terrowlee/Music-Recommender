# 输出规范（output-format）

> 本文件由 SKILL.md 按需加载：**交付推荐前必读**。包含推荐输出格式、导入歌单、HTML 交付。

## 输出格式

- 按**风格**分组（粗体显示风格名，如 **Soul-Funk**、**Neo-Soul**）
- 歌曲格式：**歌曲名 - 歌手** 【BPM 预估】
  - BPM 无权威数据源（Discogs / Apple Music 均不提供官方 BPM），一律标注为预估值，不得当作精确数据呈现。
- 每首歌后紧跟一句**两层推荐理由**：
  1. **偏好关联层**：引用画像中的具体证据（锚点歌曲、高频制作人、近期趋势、用户喜欢的音色/年代），说明为什么推给你；
  2. **内容特质层**：描述这首歌本身的亮点（年代质感 / 和弦色彩 / 声场贴耳感 / 人声微观质感 / Bassline 特征，至少体现一项）。
  - 禁止空泛表述（如"很适合你""你会喜欢"），必须落到具体证据和具体特质。
- 每组下方可加一句该风格的核心特色总结
- **推荐密度**：默认 20-50 首/次；用户指定数量时按用户要求（如"推荐 10 首"就恰好 10 首）
- **制作人延伸备注**：候选曲命中画像制作人库时，推荐理由注明"这是由 [制作人] 制作的，就像你喜欢的那首 [歌名] 一样"
- 结尾必须有：**"3 首开胃菜 + 1 张必听专辑"**（注明专辑名）
- 偶尔留钩子："听完想深挖哪个分支，告诉我就行"
- **建歌单询问**：已装并登录 ncm-cli 的用户，推荐交付后主动询问是否建歌单。规则见 [ncm-cli-integration.md](ncm-cli-integration.md)。
- **HTML 交付**：推荐 **10 首及以上**时，默认同时交付一份同主题 HTML 歌单/报告页（自包含样式、按风格分组、含理由与网易云链接），与聊天正文并列；用户明确"只要列表/不要文件"或只推少量歌曲时跳过。

## 导入歌单

当用户说"**导入歌单**"或"**我需要导入歌单**" → **只输出纯文本歌单，格式为"歌曲名 - 歌手"，每行一首，不要任何多余文字、介绍、分割线或礼貌用语。直接开始列表，直到结束。**
