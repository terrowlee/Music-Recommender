# music-recommender · 音乐推荐官

一个 [Agent Skills](https://agentskills.io/) 技能，把 AI 变成你的音乐推荐官：按你的口味画像（风格 / BPM / 年代 / 音色）推荐歌曲，严格过滤引流污染的各类版本，只推真实存在的原版音源。还可选集成网易云音乐 CLI，把推荐结果直接创建成网易云歌单。

## 为什么做这个

**1. 平台的风格数据不可信。**
国内音乐平台会把绝大多数歌曲的流派标成"流行"——你喜欢按风格听歌，但按平台标签找歌永远跑偏。所以本技能的风格判定不依赖平台标签，而以 Discogs 等权威元数据源和歌曲本身的编曲、节奏、音色特征为准。

**2. 推荐被引流污染，越来越难听。**
算法把翻唱版、DJ 版、降速增速版推上来，原曲越来越难找到。所以本技能内置严格的"引流污染过滤"：翻唱、DJ 版、Sped Up / Slowed、8-bit、纯伴奏等一律排除，只保留原版音源、官方 Live 和官方收录的 Remix。

## 核心特性

- **先分析，后提问**：新用户先分析歌单/听歌排行生成画像初稿，再基于画像做选择题式确认，不凭空问抽象问题；已有画像的老用户走轻量问答（心情/方向），按回答动态调整推荐方向
- **按风格听歌**：严格按流派/风格分组推荐，场景描述会转译为风格诉求
- **个性化画像**：填写口味模板，或用"分析新歌单"从你的常听歌单自动生成画像
- **引流污染过滤**：翻唱 / DJ 版 / 降速增速版 / 8-bit / 伴奏版等全部排除
- **数量保障**：指定"推荐 N 首"就恰好交付 N 首，候选不足时放宽风格限制继续找，但绝不编造歌名
- **锚点校准 + 反馈闭环**：用你最爱的那几首歌作校准标尺，每轮推荐后收集反馈写回画像，越用越准
- **近期趋势加权**：自动识别你最近的口味变化（听歌排行驱动），约 40% 的推荐配额分给近期风格，不困在旧画像里
- **不重复推荐**：自动记录推荐历史，推过的歌不会再推
- **推荐理由有据**：每首歌附两层理由——为什么推给你（引用你的口味证据）+ 这首歌本身的亮点
- **风格判定可靠**：权威元数据源 > 歌曲本身特征 > 平台标签
- **模块化设计（渐进式披露）**：SKILL.md 只保留基础流程（约 75 行），推荐规则、问答体系、分析管线、输出规范分别放在 `references/`，按需加载，节省上下文
- **网易云音乐 CLI 集成（可选）**：把推荐结果直接创建成网易云歌单；已安装并登录 CLI 的用户，每轮推荐后会自动询问是否建歌单，详见 `references/ncm-cli-integration.md`

## 安装

把 `music-recommender/` 目录整体复制到你使用的 Agent 产品的技能目录即可（需支持 [Agent Skills](https://agentskills.io/specification) 标准）。

## 使用

### 第一步：建立口味画像

安装后直接跟推荐官对话即可，默认流程是**先分析、后提问、最后推荐**：

1. **先拿数据**：推荐官会先问是否装网易云 CLI（装了可分析红心歌单与听歌排行），或者请你粘贴一份常听歌单；
2. **自动分析**：从数据生成画像初稿（风格分布、分支、BPM 甜区、高频艺人/制作人、近期趋势）；
3. **基于画像提问**：只问三类——确认纠偏（"数据显示你最爱 X，还准吗？"）、补空白（审美维度选择题：和弦色彩/人声质感/声场/歌词主题）、本轮诉求（心情/数量/金曲还是冷门）；
4. **确认生效**：画像摘要请你确认后开始推荐。

没有歌单、也不装 CLI 的纯新用户，推荐官会用选项式引导（举歌手例子、不抛抽象术语）快速建画像。已有画像的老用户，之后每轮只需回答 1-2 个轻量问题。

### 日常使用

- "推荐 20 首 Neo-Soul" → 按风格推荐恰好 20 首
- "继续给我 X 风格" → 按该风格深挖
- "律动感要更强" → 按画像的律动映射执行（BPM 取区间上沿、加重贝斯）
- "按场景分组" → 推荐完成后按场景重新分组展示（深夜暧昧/独处漫步/微醺派对/雨夜开车）
- "导入歌单" → 输出纯文本歌单，方便复制
- "给我建一个歌单" → （可选）对接网易云创建歌单，见 `references/ncm-cli-integration.md`
- 推荐 ≥10 首时默认附一份 HTML 歌单页，方便预览分享

## 工作原理（文件地图）

SKILL.md 是入口与索引（基础流程 + 三条红线摘要），详细规则按需加载：

| 文件 | 内容 | 读取时机 |
|---|---|---|
| `SKILL.md` | 基础流程：画像读取、流程入口、工作流总览、风格判定、交互触发、网易云启动条件 | 激活时自动加载 |
| `references/recommendation-rules.md` | 锚点校准、关系图谱、方向确认、反馈闭环、近期趋势、历史去重、搜索策略、推荐铁律、数量保障 | 每次推荐前 |
| `references/onboarding.md` | 新手引导（先分析后提问）、老用户轻问答、画像定向提问、从零问答兜底 | 建画像 / 问答时 |
| `references/analysis-pipeline.md` | 多数据源分析、Discogs 制作人信用、分支识别、BPM 甜区、排除确认 | 分析歌单/红心时 |
| `references/output-format.md` | 输出格式、两层理由、HTML 交付、导入歌单 | 交付推荐前 |
| `references/ncm-cli-integration.md` | 网易云安装/登录/搜索/歌单管理、Windows 编码与引号坑、常见问题 | 网易云操作时 |

## 目录结构

```
music-recommender/
├── SKILL.md                          # 入口与索引（基础流程，~75 行）
├── README.md
├── LICENSE                           # MIT
├── assets/
│   ├── user-profile-template.md      # 口味画像模板（留空待填）
│   ├── user-profile.md               # （运行时生成）你的口味画像
│   ├── feedback-log.md               # （运行时生成）反馈记录
│   └── recommendation-history.md     # （运行时生成）推荐历史去重
└── references/
    ├── recommendation-rules.md       # 推荐执行规则（循环/机制）
    ├── onboarding.md                 # 问答体系（新手/老用户流程）
    ├── analysis-pipeline.md          # 分析管线（歌单/红心分析）
    ├── output-format.md              # 输出规范（含 HTML 交付）
    └── ncm-cli-integration.md        # 网易云歌单集成
```

> 运行时文件由推荐官自动创建维护，无需手动管理；仓库已通过 .gitignore 排除 `user-profile.md`（含个人口味数据）。
