# 问答体系（onboarding）

> 本文件由 SKILL.md 的"推荐流程入口"按需加载。包含：新手引导（先分析后提问）、老用户流程、从零问答兜底、画像定向提问。

## 新手引导（先分析，后提问，最后推荐）

新用户不了解本技能的用法，且多数用户不熟悉音乐术语。默认流程：**先拿数据、先分析，再基于画像初稿提问，最后推荐**——不要在没有任何数据时从头问一堆抽象问题。

0. **先问网易云（仅首次）**：检测 ncm-cli（`ncm-cli --version`）。
   - **未安装** → 开场第一句话先问："你用网易云音乐吗？装一下网易云命令行工具，我就能分析你红心的歌曲，推荐会更准。要不要我现在帮你装？"
     - 要装 → 按 [ncm-cli-integration.md](ncm-cli-integration.md) 执行安装 + 引导登录；**安装后必须把开放平台链接发给用户，引导其申请 App ID / Private Key**（见集成文档"获取 API 凭证"步骤，链接不发用户会卡住）。
     - 不要 → 请用户**粘贴一份常听歌单**（"分析新歌单"）；也没有歌单 → 直接进入"从零问答"。
   - **已安装并登录** → 跳过本步，直接进入"先分析，后提问"。

1. **先分析，后提问**：
   a. **拿数据**：ncm-cli 模式拉取红心歌单 + 听歌排行 + 最近播放；无 ncm-cli 则用用户粘贴的歌单；
   b. **自动分析**：按 [analysis-pipeline.md](analysis-pipeline.md) 生成画像初稿（风格分布、分支、BPM 甜区、高频艺人/制作人、近期趋势）；
   c. **基于画像初稿提问**——只问三类，不从头问：
      - **确认纠偏**："数据显示你最爱 [画像初稿中占比最高的 1-2 个分支]，还准吗？"（展示 1-2 个高频艺人帮助回忆）
      - **补空白**（分析覆盖不到的）：
        - 锚点歌曲确认：从高频曲目里挑 3-5 首请用户确认或替换；
        - 审美维度选择题：和弦色彩 / 人声质感 / 声场 / 歌词主题 4 组（每题必须给选项，用"比如 XXX 那种感觉"引导，不抛抽象术语）；
        - 排除项确认：开放式提问"有没有一听就跳过的歌/艺人/风格？"，给 2-3 个常见大类做引导示例（标注为示例非默认），确认后写入画像；
      - **画像定向提问（举一反三）**：根据画像内容设计针对性问题，不局限于固定清单——从画像数据里找可深挖的点，用选择题引导用户确认。示例：画像中黑人音乐/律动类分支占比高 → 问律动偏好（"想要更强的律动，还是更丝滑的？"）；某地域/语言分支多（如日系）→ **不预设固定选项**（如"只有 City Pop 和 R&B 两种"这类两分法是错的），问"这个方向这轮继续深挖，还是换换口味？"，或从画像数据里取该分支的实际细分作为选项；Funk/Disco 类分支刚加入 → 问"这轮要不要多来点？"；某分支高频但没细化过 → 问该分支的细分偏好；
      - **本轮诉求**：本次心情（轻松/沉浸/想动起来/想静下来）、数量、金曲大杂烩还是冷门遗珠。
   - **提问节奏**：每轮最多 2 问；审美维度 4 组选择题拆 2 轮进行。

2. **收尾**：画像初稿 + 回答整理写入 `assets/user-profile.md`（按模板结构），展示摘要请用户确认；确认后开始推荐。已装 ncm-cli 的用户，首次推荐交付时主动询问是否建网易云歌单。

3. **从零问答（兜底，仅当无任何数据来源）**：不装 ncm-cli、也没有歌单可粘贴时才用。用选项式引导，一次最多 2 问，**不要抛抽象流派名词**：
   - 锚点歌曲：给例子帮用户理解——用大众熟知歌手或用户自己提到的歌手做参照（"类似 XXX 那种丝滑的？还是 XXX 那种清亮的？"）；
   - 常听风格：举歌手例子让用户选，而非"你喜欢什么流派"；
   - 节奏感：慢板抒情 / 中板律动 / 快板舞曲；
   - 排除项：开放式提问 + 用 2-3 个常见大类做引导示例（如民谣类、摇滚类、电子舞曲类，标注为示例而非默认排除）；
   - 本次心情。
   收尾同上。

4. 用户在任何阶段说"先直接推荐" → 用已有信息（哪怕只有锚点 + 心情）先推，画像之后补全。

## 已有画像的推荐流程（老用户）

用户画像存在（`assets/user-profile.md` 非空）时，**不重新分析歌单**，走轻量问答流程：

1. **读画像**：读取画像 + 反馈日志 + 推荐历史（去重依据）。
2. **轻量提问（1-2 问）**：问本轮诉求，给选项引导——
   - 心情：想动起来 / 想静下来 / 微醺暧昧 / 专注 / 治愈 / 随便；
   - 方向：今天偏向什么风格？还是按画像来？
   - 数量：默认 20-50 首，用户指定则按指定；
   - 金曲大杂烩还是冷门遗珠（用户未指定时按"熟悉艺人禁热门金曲"默认）；
   - **画像定向问题（可选）**：按画像内容加一问（举一反三），如律动类分支占比高时问"今天律动想强一点还是丝滑一点？"，新分支刚加入时问"要不要试试新分支？"。
3. **心情 → 推荐方向动态调整**（按回答临时调整，**不写死具体流派**——从用户画像中选取符合情绪方向的分支，尊重画像的严禁流派与沉睡分支）：
   - 想动起来 → 选画像中律动感强、BPM 偏快的分支，BPM 取区间上沿；
   - 想静下来 → 选画像中舒缓的分支，BPM 取区间下沿；
   - 微醺暧昧 → 选画像中氛围私密、主题暧昧的分支优先；
   - 专注 → 选画像中器乐性强、中速律动的分支优先；
   - 治愈 → 选画像中温暖向的分支优先；
   - 随便 → 按近期趋势约 40% + 整体画像分配。
4. **本轮覆盖机制（per-round overrides）**：用户本轮说的临时排除/加权（如"今天不要 X""多来点 Y"）**仅本轮生效**，不写入画像；用户明确"以后都这样"才更新画像字段。
5. **近期趋势刷新时机**：不每轮分析歌单；每约 5 轮、或用户说"重新分析/口味变了"、或建歌单后发现红心明显变化时，才拉一次听歌排行刷新"近期趋势"字段。
6. **探索提问（可选）**：用户没指定方向时，可问一句"今天想不想试试新分支？"（如画像外的新风格），想试则按新分支小批量给 3-5 首探索。
7. **趋势信号**：连续 3 轮以上同向回答（如总想动起来），主动问一句"要不要把这个方向更新进画像？"。
