# 推荐执行规则（recommendation-rules）

> 本文件由 SKILL.md 强制引用：**每次推荐前必读**。包含推荐准确度机制（循环类）、搜索策略、推荐铁律。

## 推荐准确度机制

### 锚点歌曲校准（最优先）

画像中的"锚点歌曲"是用户口味最具体的标尺。推荐时：

- 优先匹配锚点歌曲的**声音、编曲、制作质感**（音色、律动、混音、年代感），而不是粗粒度流派标签；
- 候选曲与锚点的声音气质越接近，优先级越高；
- 锚点为空时，以画像中的风格、年代、音色描述为基准。

### 艺人关系图谱扩展

需要扩大候选池时，优先沿**锚点艺人/熟悉艺人的关系网络**向外挖：

1. 该艺人的**制作人**的其他作品；
2. 该艺人的**合作嘉宾、客串、feat.**；
3. 同专辑/同厂牌的**乐手与创作者**的 solo 作品；
4. 最后才是按风格标签搜索新艺人。

关系网络扩展出的歌曲声音更接近用户口味，比标签搜索更准。

### 方向确认（推荐前，优先用提问）

推荐方向不明确时，**优先用提问确认**（1-2 个关键问题：风格、心情、金曲还是冷门），而不是直接推一堆让用户试错。仅当画像无锚点歌曲、且该风格方向此前未校准过、提问也问不清时，才用"5 首校准曲"试方向：给 5 首代表性校准曲 → 用户确认方向 → 再扩展到目标数量；用户说"不用校准"或反馈记录已覆盖时跳过。

### 反馈闭环（越用越准）

每轮推荐交付后：

1. 追问一句反馈："这几首里哪些喜欢、哪些想跳过？整体方向对不对？"
2. 把反馈写入 `assets/feedback-log.md`（不存在则创建）：喜欢的方向、跳过的歌/艺人、整体评价、日期；
3. 用户给出负反馈时，立即据此修正画像相关字段（如补充排除项、收紧风格），并重新推荐一批替换；
4. 之后每次推荐前，读取该文件作为校准依据。反馈积累越多，推荐越准。

### 近期趋势加权（跟随变化的口味）

人的口味是动态的，推荐不能只反映"过去的你"：

1. 画像中的"近期趋势"字段记录用户最近的风格倾向（来源：反馈、红心分析、新歌单分析）；
2. **每轮推荐中，符合近期趋势的风格应占总配额约 40%**，其余按整体画像分配；该比例可在画像中调整；
3. 近期趋势与整体画像明显偏离时，主动跟用户确认一句，是否要更新整体画像；
4. 画像无"近期趋势"记录时，全部配额按整体画像分配。

### 推荐历史去重（不重复推同一首歌）

1. 每轮推荐后，把本轮曲目（歌曲名 - 歌手，附日期）写入 `assets/recommendation-history.md`（不存在则创建）；
2. 每次推荐前先读取该文件，已推荐过的歌默认不再推荐；
3. 仅当用户明确要求"再推一次"，或某风格方向的历史记录已穷尽时，才可重复推荐，并注明"之前推过"。

## 搜索策略

怎么找到歌和怎么挑歌同样重要。每次推荐前主动决策：

1. **搜什么**：默认搜单曲；用户要主题/氛围合集时混合搜专辑。
2. **关键词组合**：多维组合使用，不要只用单个流派词——
   - 英文流派标签（Neo-Soul、City Pop、Nu-Disco 等）
   - 年代词（90s R&B、80s funk 等）
   - 情绪/质感词（smooth、intimate、neon 等）
   - 艺人风格词（"类似 XXX 的艺人"、"XXX produced"）
3. **多轮并行**：复杂需求用 2-4 组关键词分别搜索，合并结果后去重；简单需求单轮即可。
4. **关系图谱优先**：按"艺人关系图谱扩展"，优先用制作人、合作者名字作搜索关键词。
5. **去重来源**：排除 `assets/recommendation-history.md` 中已推荐歌曲；ncm-cli 模式下同时排除用户红心歌曲（依据：搜索结果的 `liked` 字段）。

## 推荐铁律

### 1. 只推原版音源（引流污染过滤）

推荐质量的最大敌人是引流衍生的各种版本，必须执行以下过滤：

**禁止（引流污染版本）**：

- 翻唱（Cover）
- DJ 版、抖音热歌版、网络神曲版
- 降速版（Slowed）、增速版（Sped Up）等变速版本
- 8-bit 版、纯伴奏版、钢琴版等衍生版本
- 非官方 Remix、Tribute

**允许**：

- 官方 Live 版
- 官方专辑收录的 Remix

**识别方法**：标题或副标题含 Cover、DJ、Remix（非官方）、Sped Up、Slowed、8-bit、伴奏、XX 版等关键词的，一律排除。同一首歌存在多个版本时，只取原版音轨。

### 2. 必须真实，绝不编造

- 每首歌必须能在 Spotify / Apple Music 找到。
- 绝不编造歌名。候选曲不够时按"数量保障机制"处理，而不是编造凑数。

### 3. 数量保障机制（查漏补缺循环）

用户指定数量时（如"推荐 20 首"），最终输出**必须恰好等于**用户要求的数量，按以下顺序执行：

1. 先严格按画像约束筛选；
2. 不够时**放宽风格限制**（扩大流派范围、放宽 BPM 区间），继续搜索；
3. 两条红线**永不放宽**：**严禁流派**（画像中配置）、**只推原版音源**；
4. 持续搜索直到凑够数量；任何情况下**不得编造歌名凑数**；
5. 多轮扩大搜索后确实找不到足够真实歌曲时，如实告知用户缺口和原因，不用编造收尾。

### 4. 其他约束

- **每艺人最多 1 首**：同一歌手/艺人在一次推荐中最多出现 1 首。**例外**：结尾的"1 张必听专辑"不受此限制。
- **熟悉艺人禁热门金曲（默认）**：画像"我已熟悉的领域/艺人"中的艺人，默认避开其热门金曲，改推冷门遗珠、Side Project 或新专；若方向确认时用户明确要"金曲/热门"，则不受此限。
- **个性化比例约束**：如用户在画像中配置了语言比例、年代比例等个性化约束，按其配置执行；画像未配置则不设比例限制。
- **拒绝客服腔**：不要说"希望对你有帮助""这是一个好问题"。像老朋友一样直接说话。
